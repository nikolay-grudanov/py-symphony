# Build Orchestrator - Чеклист завершения

## Обзор

Чеклист определяет критерии завершения задач и workflows. Build Orchestrator не может считать задачу завершенной, пока все пункты чеклиста не выполнены.

## Чеклист для архитектурных задач

### Для Platform Architect

- [ ] **ADR создан**
  - ADR содержит все необходимые разделы:
    - [ ] Status (Accepted/Rejected/etc.)
    - [ ] Context (проблема, требование)
    - [ ] Рассмотренные альтернативы (минимум 2)
    - [ ] Решение с обоснованием
    - [ ] Последствия (плюсы/минусы)
    - [ ] Соответствие SPEC.md (ссылки на разделы)

- [ ] **ADR approved**
  - ADR имеет approval от соответствующего архитектора
  - Дата approval указана
  - Имя архитектора указано

- [ ] **Соответствие SPEC.md**
  - Решение соответствует требованиям SPEC.md
  - Ссылки на соответствующие разделы SPEC.md предоставлены
  - Нет противоречий с SPEC.md

- [ ] **Артефакты созданы**
  - [ ] ADR документ записан в docs/adr/
  - [ ] Диаграммы архитектуры (если применимо)
  - [ ] Примеры использования (если применимо)

### Для Agent Runtime Architect

- [ ] **ADR создан**
  - ADR для runtime архитектуры содержит:
    - [ ] Статус
    - [ ] Контекст (требования к runtime)
    - [ ] Альтернативы (минимум 2)
    - [ ] Решение
    - [ ] Последствия
    - [ ] Соответствие SPEC.md

- [ ] **ADR approved**
  - Approval от runtime архитектора
  - Дата указана
  - Имя архитектора указано

- [ ] **Соответствие SPEC.md**
  - Соответствует требованиям к runtime из SPEC.md
  - Ссылки на разделы SPEC.md

- [ ] **Артефакты созданы**
  - [ ] ADR документ
  - [ ] Runtime спецификации (если применимо)
  - [ ] Примеры конфигураций (если применимо)

## Чеклист для задач реализации

### Для Implementation Engineer

- [ ] **Код реализован**
  - [ ] Все требования из ADR реализованы
  - [ ] Код соответствует code standards (PEP 8, type hints, docstrings)
  - [ ] Нет TODO или FIXME в production коде (кроме documented)
  - [ ] Error handling реализован
  - [ ] Логирование добавлено где необходимо

- [ ] **Unit tests написаны**
  - [ ] Тесты для всех публичных методов
  - [ ] Тесты для edge cases
  - [ ] Тесты для error paths
  - [ ] Все тесты проходят
  - [ ] Coverage соответствует требованиям (обычно > 80%)

- [ ] **Документация создана**
  - [ ] Docstrings для всех публичных методов
  - [ ] README обновлен (если применимо)
  - [ ] API документация создана (если применимо)
  - [ ] Примеры использования предоставлены

- [ ] **Pull Request создан**
  - [ ] PR имеет ясное описание изменений
  - [ ] PR ссылается на соответствующий issue/ADR
  - [ ] CI/CD проходит (если настроен)
  - [ ] Code review не имеет критических комментариев

## Чеклист для задач интеграции

### Для Integration Architect

- [ ] **ADR для контракта создан**
  - [ ] ADR описывает контракт интеграции
  - [ ] Интерфейсы определены четко
  - [ ] Альтернативы рассмотрены
  - [ ] Решение обосновано
  - [ ] Последствия описаны

- [ ] **ADR approved**
  - Approval от integration архитектора
  - Дата указана
  - Имя архитектора указано

- [ ] **Контракты определены**
  - [ ] Интерфейсы четко определены
  - [ ] Input/output спецификации
  - [ ] Error handling контракты
  - [ ] Retry логика (если применимо)
  - [ ] Timeout настройки

- [ ] **Артефакты созданы**
  - [ ] ADR документ
  - [ ] Спецификации контрактов (JSON schema, OpenAPI, и т.д.)
  - [ ] Примеры использования
  - [ ] Mock implementations (если применимо)

- [ ] **Соответствие требованиям**
  - [ ] Контракт соответствует требованиям бизнеса
  - [ ] Контракт соответствует возможностям внешней системы
  - [ ] Контракт соответствует ADR от platform architect (если применимо)

## Чеклист для задач тестирования

### Для Test Engineer

- [ ] **Unit tests написаны**
  - [ ] Тесты покрывают все requirements
  - [ ] Тесты для всех методов
  - [ ] Edge cases протестированы
  - [ ] Error paths протестированы
  - [ ] Mocks/stubs используются правильно
  - [ ] Тесты изолированы (не зависят друг от друга)

- [ ] **Integration tests написаны**
  - [ ] Тесты покрывают основные workflows
  - [ ] Тесты интеграции с внешними системами (если применимо)
  - [ ] Тесты для error scenarios
  - [ ] Тесты устойчивы к задержкам сети

- [ ] **Тесты проходят**
  - [ ] Все unit tests проходят
  - [ ] Все integration tests проходят
  - [ ] Нет flaky tests
  - [ ] Tests выполняются быстро (< 5 сек для unit, < 30 сек для integration)

- [ ] **Coverage соответствует требованиям**
  - [ ] Coverage >= требуемого значения (обычно > 80%)
  - [ ] Критический код покрыт на 100%
  - [ ] Coverage report доступен

- [ ] **Документация создана**
  - [ ] README обновлен с инструкциями по запуску тестов
  - [ ] pytest.ini или подобный конфиг настроен
  - [ ] Test fixtures документированы
  - [ ] Test conventions описаны

## Чеклист для задач верификации

### Для Verification Agent

- [ ] **Все артефакты проверены**
  - [ ] ADR проверен и соответствует требованиям
  - [ ] Код проверен и соответствует ADR
  - [ ] Код соответствует code standards
  - [ ] Тесты проверены и покрывают требования
  - [ ] Документация проверена и полна

- [ ] **Соответствие SPEC.md**
  - [ ] Решение соответствует требованиям SPEC.md
  - [ ] Нет противоречий с SPEC.md
  - [ ] Ссылки на разделы SPEC.md предоставлены

- [ ] **QA Gates пройдены**
  - [ ] Для архитектурных задач: ADR создан и approved
  - [ ] Для задач реализации: код соответствует ADR и standards
  - [ ] Для задач интеграции: контракт определен и соответствует требованиям
  - [ ] Для задач тестирования: coverage соответствует требованиям
  - [ ] Для всех задач: documentation полная

- [ ] **Отчет о верификации создан**
  - [ ] Все проверки документированы
  - [ ] Проблемы (если есть) задокументированы
  - [ ] Решение принято (Passed / Failed / Needs Rework)
  - [ ] Рекомендации предоставлены

- [ ] **Проблемы решены** (если были)
  - [ ] Критические проблемы исправлены
  - [ ] Некритические проблемы задокументированы
  - [ ] Improvement suggestions записаны

## Чеклист для полного workflow

### Build Orchestrator

- [ ] **Все задачи созданы**
  - [ ] Все подзадачи определены
  - [ ] Зависимости между задачами определены
  - [ ] Приоритеты установлены
  - [ ] Дедлайны установлены

- [ ] **Все задачи назначены**
  - [ ] Каждая задача назначена соответствующему агенту
  - [ ] Агенты приняли задачи
  - [ ] Контекст предоставлен

- [ ] **Все задачи выполнены**
  - [ ] Каждая задача имеет статус "Completed"
  - [ ] Все артефакты созданы
  - [ ] Все QA Gates пройдены

- [ ] **Все handoffs успешны**
  - [ ] Передача между агентами успешна
  - [ ] Нет отклоненных handoffs
  - [ ] Контекст передан полностью

- [ ] **Все ADR созданы и approved**
  - [ ] Все необходимые ADR созданы
  - [ ] Все ADR approved
  - [ ] ADR соответствуют SPEC.md

- [ ] **Verification пройден**
  - [ ] Verification выполнен
  - [ ] Результат: Passed
  - [ ] Отчет о верификации создан

- [ ] **Все артефакты собраны**
  - [ ] ADR документы
  - [ ] Код
  - [ ] Тесты
  - [ ] Документация
  - [ ] Отчеты verification

- [ ] **Финальный отчет создан**
  - [ ] Краткое описание того, что было выполнено
  - [ ] Ссылки на все артефакты
  - [ ] Статус QA Gates
  - [ ] Следующие шаги (если есть)

## Правила завершения

### Условия для завершения задачи

Задача может быть завершена только если:

1. **Все пункты соответствующего чеклиста выполнены**
2. **Все QA Gates пройдены**
3. **Нет открытых проблем или блокировок**
4. **Все артефакты созданы и доступны**

### Условия для завершения workflow

Workflow может быть завершен только если:

1. **Все задачи workflow завершены**
2. **Все handoffs успешны**
3. **Verification пройден с результатом Passed**
4. **Финальный отчет создан**
5. **Нет блокировок для других workflows**

### Прерывание workflow

Workflow может быть прерван если:

1. **Критическая ошибка**, которую невозможно решить
2. **Дедлайн пропущен** и решение о прекращении принято
3. **Требования изменились** и workflow больше не нужен
4. **Решение руководителя** о прекращении

При прерывании:

- [ ] Логировать причину прерывания
- [ ] Сохранить все созданные артефакты
- [ ] Создать отчет о прогрессе
- [ ] Уведомить всех вовлеченных агентов

## Примеры использования чеклиста

### Пример 1: Простая задача

```
## Задача: Реализовать PaymentService

### Чеклист Implementation Engineer
- [x] Код реализован
- [x] Unit tests написаны
- [x] Документация создана
- [x] Pull Request создан

### Чеклист Verification Agent
- [x] Все артефакты проверены
- [x] Соответствие SPEC.md
- [x] QA Gates пройдены
- [x] Отчет о верификации создан

### Результат: Задача завершена ✅
```

### Пример 2: Сложный workflow

```
## Workflow: Добавить email notification service

### Чеклист Build Orchestrator
- [x] Все задачи созданы (5 задач)
- [x] Все задачи назначены
- [x] Все задачи выполнены
- [x] Все handoffs успешны
- [x] Все ADR созданы и approved (3 ADR)
- [x] Verification пройден
- [x] Все артефакты собраны
- [x] Финальный отчет создан

### Результат: Workflow завершен ✅
```

### Пример 3: Задача с отклонением

```
## Задача: Реализовать PaymentService

### Чеклист Implementation Engineer
- [x] Код реализован
- [x] Unit tests написаны
- [ ] Документация создана ❌
- [x] Pull Request создан

### Result: Задача отклонена
Причина: Документация отсутствует
Action: Переназначить инженеру для создания документации
```

## Метрики качества

Для оценки качества выполнения чеклиста используются следующие метрики:

1. **Процент выполнения чеклиста**
   - 100%: Все пункты выполнены ✅
   - 80-99%: Почти все пункты выполнены, могут быть некритические пропуски
   - <80%: Значительные пропуски, требуется доработка

2. **Количество пропущенных пунктов по категориям**
   - Критические пропуски: Блокируют завершение задачи
   - Некритические пропуски: Можно исправить post-factum

3. **Время выполнения чеклиста**
   - Время от начала задачи до завершения всех пунктов
   - Сравнение с оценкой времени

4. **Количество итераций**
   - Сколько раз задача возвращалась на доработку
   - Цель: Минимум итераций (ideally 1)
