# Implementation Engineer - Чеклист завершения

## Обзор

Чеклист определяет критерии завершения при реализации кода. Implementation Engineer не может считать реализацию завершенной, пока все пункты не выполнены.

## Чеклист для реализации

### Код

- [ ] **Код соответствует ADR**
  - [ ] Архитектурное решение из ADR реализовано
  - [ ] Все требования из ADR покрыты
  - [ ] Никаких архитектурных изменений без ADR

- [ ] **Код соответствует спецификациям**
  - [ ] Контракты интеграции соблюдены
  - [ ] API контракты соблюдены
  - [ ] Data models соответствуют спецификации

- [ ] **Code standards соблюдены**
  - [ ] PEP 8 compliance
  - [ ] Type hints для всех функций
  - [ ] Docstrings для всех public functions/classes
  - [ ] Maximum line length (79 или 88 chars)
  - [ ] Imports organized

- [ ] **Clean code principles**
  - [ ] Имена переменных/функций описательные
  - [ ] Функции короткие (< 20 lines)
  - [ ] Нет дублирования (DRY)
  - [ ] SRP (Single Responsibility Principle)
  - [ ] Code организован логически

- [ ] **Error handling**
  - [ ] Все ожидаемые ошибки обработаны
  - [ ] Custom exceptions определены
  - [ ] Error messages информативные
  - [ ] Errors логируются с контекстом
  - [ ] Fallback механизмы где применимо

### Тесты

- [ ] **Unit tests написаны**
  - [ ] Все public methods протестированы
  - [ ] Edge cases протестированы
  - [ ] Error paths протестированы
  - [ ] Mocking для external dependencies
  - [ ] Test fixtures созданы

- [ ] **Integration tests**
  - [ ] Интеграции с внешними API протестированы
  - [ ] Database integration tests
  - [ ] Test data setup/teardown
  - [ ] Integration tests с staging environment

- [ ] **Test coverage**
  - [ ] Coverage > target (обычно > 80%)
  - [ ] Critical paths 100% coverage
  - [ ] Coverage report доступен
  - [ ] Uncovered code reviewed

- [ ] **Все tests проходят**
  - [ ] Unit tests passing
  - [ ] Integration tests passing
  - [ ] No skipped tests (без justification)
  - [ ] Test execution time приемлемый

### Документация

- [ ] **Docstrings**
  - [ ] Docstrings для всех public functions
  - [ ] Docstrings для всех public classes
  - [ ] Google style или другой стандартный стиль
  - [ ] Args документация
  - [ ] Returns документация
  - [ ] Raises документация
  - [ ] Examples где применимо

- [ ] **README**
  - [ ] Обновлен если API изменился
  - [ ] Installation инструкции
  - [ ] Usage examples
  - [ ] API documentation links
  - [ ] Contributing guidelines

- [ ] **API documentation**
  - [ ] Autogenerated docs (Sphinx/MkDocs) если применимо
  - [ ] Examples для всех методов
  - [ ] Tutorial documentation
  - [ ] Migration guide если нужно

- [ ] **Inline comments**
  - [ ] Сложная логика прокомментирована
  - [ ] Workarounds документированы
  - [ ] TODO/FIXME comments minimized
  - [ ] No commented-out code

### Performance

- [ ] **Performance optimized**
  - [ ] Критические paths оптимизированы
  - [ ] Caching где применимо
  - [ ] Database queries оптимизированы
  - [ ] N+1 query problems избеганы

- [ ] **Benchmarks**
  - [ ] Benchmark для критических paths
  - [ ] Performance metrics записаны
  - [ ] Comparison с baseline если применимо
  - [ ] Performance tests созданы

- [ ] **Memory efficiency**
  - [ ] Memory leaks избеганы
  - [ ] Large objects handled efficiently
  - [ ] Resource cleanup (context managers)

### Безопасность

- [ ] **Input validation**
  - [ ] Все inputs валидированы
  - [ ] Type checking
  - [ ] Range checking
  - [ ] Custom validation rules

- [ ] **SQL injection prevention**
  - [ ] Parameterized queries
  - [ ] ORM usage
  - [ ] No string concatenation для queries

- [ ] **XSS prevention**
  - [ ] Output encoding
  - [ ] Content security policy если применимо
  - [ ] Sanitization user input

- [ ] **Password handling**
  - [ ] Passwords hashed (bcrypt, argon2)
  - [ ] No plain text storage
  - [ ] Secure random generation

- [ ] **Dependencies**
  - [ ] Dependencies checked for vulnerabilities
  - [ ] Dependencies up-to-date
  - [ ] No known security issues

### Code Review

- [ ] **Pull Request создан**
  - [ ] PR с ясным описанием изменений
  - [ ] Ссылки на ADR и issues
  - [ ] Changelog если применимо
  - [ ] Breaking changes документированы

- [ ] **CI/CD passes**
  - [ ] All tests pass в CI
  - [ ] Linting passes
  - [ ] Type checking passes (mypy)
  - [ ] Security scans pass

- [ ] **Code review в процессе**
  - [ ] Requested reviewers
  - [ ] Comments addressed
  - [ ] Changes pushed
  - [ ] Re-review если нужно

## Чеклист для handoff

### К verification-agent

- [ ] **Код готов к верификации**
  - [ ] Код соответствует ADR
  - [ ] Код соответствует code standards
  - [ ] Все tests проходят
  - [ ] Документация создана

- [ ] **Артефакты подготовлены**
  - [ ] Код доступен (branch/tag)
  - [ ] Tests доступны
  - [ ] Documentation доступна
  - [ ] Pull request готов

- [ ] **Handoff package подготовлен**
  - [ ] ADR ссылка
  - [ ] Спецификация ссылка
  - [ ] Реализация summary
  - [ ] Тесты summary
  - [ ] Особенности implementation
  - [ ] Known limitations

### К test-engineer

- [ ] **Код готов для integration testing**
  - [ ] Unit tests написаны
  - [ ] Mock API specs доступны
  - [ ] Test scenarios определены
  - [ ] Test data готово

- [ ] **Требования к testing**
  - [ ] Test scenarios document
  - [ ] Happy path scenarios
  - [ ] Error path scenarios
  - [ ] Edge case scenarios
  - [ ] Performance scenarios

- [ ] Unit tests написаны и проходят
- [ ] Integration tests написаны и проходят
- [ ] Test coverage > target
- [ ] Docstrings для всех public functions/classes
- [ ] README обновлен если нужно
- [ ] API documentation создана если нужно
- [ ] Performance оптимизирована где нужно

- [ ] Handoff подготовлен для test-engineer

## Post-handoff checklist

После передачи verification-agent:

- [ ] Verification agent принял код
- [ ] Feedback от verification-agent получен
- [ ] Issues исправлены если есть
- [ ] Updated PR создан если нужно
- [ ] Code готов к merge

## Критерии качества кода

### Readability
- [ ] Имена описательные и согласованные
- [ ] Code легко читается
- [ ] Comments где нужно
- [ ] Docstrings полные

### Maintainability
- [ ] Нет дублирования
- [ ] Functions короткие и focused
- [ ] Modules организованы логически
- [ ] Dependencies минимальны

### Testability
- [ ] Code легко тестируем
- [ ] Mocking dependencies возможно
- [ ] Tests comprehensive
- [ ] Test coverage > target

### Performance
- [ ] Critical paths оптимизированы
- [ ] No performance bottlenecks
- [ ] Efficient use of resources
- [ ] Benchmarks где применимо

### Security
- [ ] Inputs validated
- [ ] SQL injection prevented
- [ ] XSS prevented
- [ ] Passwords hashed
- [ ] Dependencies secure

## Common pitfalls checklist

- [ ] Нет hardcoded секретов
- [ ] Нет commented-out code
- [ ] Нет TODO/FIXME в production code (без documented justification)
- [ ] Нет print statements (use logging)
- [ ] Нет unused imports
- [ ] Нет unused variables
- [ ] Нет dead code
- [ ] Нет duplicated code
- [ ] Нет overly complex functions
- [ ] Нет magic numbers (use constants)
