# Чек-лист завершения: Platform Architect

## Общий принцип

Агент platform-architect завершает свою работу только когда выполнены все критерии из этого чек-листа. Критерии организованы по категориям для удобства проверки.

---

## Категория 1: Документирование архитектурных решений (ADR)

### Критерий 1.1: Все основные решения документированы

- [ ] Созданы ADR для всех архитектурных решений, влияющих на систему
- [ ] Каждый ADR содержит: контекст, решение, обоснование, альтернативы, последствия
- [ ] ADR пронумерованы и хранятся в централизованном месте

### Критерий 1.2: ADR для основных компонентов

- [ ] ADR для Workflow Loader: загрузка и парсинг WORKFLOW.md
- [ ] ADR для Config Layer: typed getters, defaults, env resolution
- [ ] ADR для Issue Tracker Client: интеграция с Linear, нормализация данных
- [ ] ADR для Orchestrator: управление состоянием, concurrency, reconciliation
- [ ] ADR для Workspace Manager: создание workspace, safety invariants
- [ ] ADR для Agent Runner: протокол интеграции с Codex app-server
- [ ] ADR для Status Surface (если применимо): интерфейсы мониторинга
- [ ] ADR для Logging: structured logs, observability

### Критерий 1.3: ADR для архитектурных слоев

- [ ] ADR для Policy Layer: repository-owned behavior
- [ ] ADR для Configuration Layer: typed config getters
- [ ] ADR для Coordination Layer: orchestrator logic
- [ ] ADR для Execution Layer: workspace + agent subprocess
- [ ] ADR для Integration Layer: tracker adapter
- [ ] ADR для Observability Layer: logs + status surface

### Критерий 1.4: ADR для технологических решений

- [ ] ADR для выбора технологий для каждого компонента
- [ ] ADR для выбора технологий для инфраструктуры
- [ ] ADR для выбора технологий для безопасности
- [ ] Обоснование выбора каждой технологии

### Критерий 1.5: ADR для архитектурных паттернов

- [ ] ADR для паттернов взаимодействия компонентов
- [ ] ADR для паттернов обработки ошибок

## Процесс проверки чек-листа

### Шаг 1: Проверка критериев

1. Пройти по всем критериям чек-листа
2. Отметить выполненные критерии
3. Идентифицировать невыполненные критерии

### Шаг 2: Анализ невыполненных критериев

1. Определить причины невыполнения
2. Оценить влияние на архитектуру
3. Определить приоритет выполнения

### Шаг 3: Завершение невыполненных критериев

1. Выполнить критерии с высоким приоритетом
2. Выполнить критерии со средним приоритетом
3. Выполнить критерии с низким приоритетом

### Шаг 4: Финальная проверка

1. Пройти по всем критериям чек-листа еще раз
2. Убедиться, что все критерии выполнены
3. Утвердить завершение работы

---

## Определение завершения работы

Работа агента platform-architect считается завершенной, когда:

1. **Минимальные требования** (Критерий завершения 1) выполнены полностью
2. **Рекомендуемые требования** (Критерий завершения 2) выполнены частично или полностью
3. **Оптимальные требования** (Критерий завершения 3) выполнены по возможности

Если критические критерии из Категории 1, 2, 3, 6 не выполнены, работа НЕ считается завершенной.

Если некритические критерии из других категорий не выполнены, работа может считаться завершенной с пометкой о незавершенных критериях.
