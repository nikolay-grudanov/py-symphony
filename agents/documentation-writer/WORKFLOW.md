# Documentation Writer - Workflow

## Workflow Overview

4-step workflow for documentation:

## Step 1: Task Analysis

### Understand requirements
- What type of documentation (README, API, User Guide, Developer Guide)
- Target audience
- Context and scope
- Required sections

### Inputs
- SPEC.md or specification
- Target audience (developers, users, ops)
- Type of documentation

## Step 2: Content Structure

### Create structure
```
## [Title]

### Quick Start (for user-facing)
- Getting started
- Installation
- Basic usage

### [Main Section]
- [Content]

### API Reference
- [Endpoints/Functions]

### Troubleshooting
- Common issues
- Solutions
```

## Step 3: Content Writing

### Write each section
- Keep it simple
- Use examples
- Be specific
- Document edge cases

### Standards
- Russian language
- Clear headers
- Working code examples
- Links between sections

## Step 4: Review and Refine

### Review checklist
- [ ] All sections present
- [ ] Examples work
- [ ] Language appropriate
- [ ] Links valid
- [ ] Complete

### Refine
- Add missing sections
- Fix unclear parts
- Verify examples

## Handoff Points

### For implementation
- implementation-engineer: clarification

### For review
- verification-agent: final review
- platform-architect: architecture approval
