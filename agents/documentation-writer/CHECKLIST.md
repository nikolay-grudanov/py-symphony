# Documentation Writer - Checklist

## Quality Gates

### Before submitting documentation:
- [ ] All required sections present
- [ ] Examples are working
- [ ] Language appropriate for audience
- [ ] Structure is consistent
- [ ] Links are valid

### Content completeness:
- [ ] Overview/summary present
- [ ] Installation instructions present
- [ ] Usage examples present
- [ ] API is documented
- [ ] Errors are documented

## Validation Checklist

### Structure
- [ ] README has required sections
- [ ] API docs complete
- [ ] User guide has troubleshooting
- [ ] Developer guide has examples

### Technical Accuracy
- [ ] Code examples work
- [ ] API matches implementation
- [ ] No outdated information

### Audience
- [ ] Language appropriate for target
- [ ] Jargon explained
- [ ] Examples relevant

## Common Pitfalls

1. **Stale documentation**: Всегда сверяться с актуальным кодом
2. **Missing examples**: Examples worth more than words
3. **Wrong audience**: Know who you're writing for
4. **Incomplete**: All important aspects should be covered
