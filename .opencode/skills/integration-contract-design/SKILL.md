# Integration Contract Design

## Описание
Навык проектирования контрактов для интеграции с внешними системами. Включает определение API интерфейсов, форматов данных, обработки ошибок, безопасности и версионирования контрактов.

## Когда использовать
- Создание новой интеграции с внешним сервисом
- Обновление существующего контракта
- Проектирование API для предоставления внешним системам
- Определение форматов обмена данными

## Когда НЕ использовать
- Для внутренних модулей без внешних интеграций
- Для написания кода интеграции
- Для простых HTTP вызовов без контракта

## Входные данные
- Документация внешнего API
- Требования к интеграции
- Бизнес-логика взаимодействия
- Требования безопасности

## Выходные данные
- Контракты интеграции (API спецификации)
- Определение форматов данных (JSON, XML)
- Схемы валидации
- Документация обработки ошибок
- Политика версионирования

## Зависимости
- architecture-design - для интеграции в общую архитектуру
- security-access-model - для обеспечения безопасности интеграции

## Режимы отказа
- Несоответствие возможностям внешнего API
- Проблемы безопасности в интеграции
- Необработанные ошибки внешнего сервиса
- Изменения в API без уведомления

## Шаблоны и чек-листы

### Шаблон Integration Contract
```markdown
# Contract: {Название интеграции}

## Endpoint
- URL: https://api.example.com/v1/resource
- Method: POST
- Auth: Bearer token

## Request
```json
{
  "field1": "string",
  "field2": "number"
}
```

## Response
### Success (200)
```json
{
  "result": "object"
}
```

### Error (4xx, 5xx)
```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "description"
  }
}
```

## Error Handling
| Code | Description | Retry |
|------|-------------|-------|
| 429  | Rate limit  | Yes   |
| 500  | Server error| Yes   |
```

### Чек-лист
- [ ] Контракты определены и задокументированы
- [ ] Обработка ошибок определена для всех кодов
- [ ] Модель безопасности определена (аутентификация, авторизация)
- [ ] Версионирование контракта определено
- [ ] Rate limiting учтён
- [ ] Примеры запросов и ответов предоставлены
- [ ] Схемы валидации определены
