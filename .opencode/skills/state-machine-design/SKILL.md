# State Machine Design

## Описание
Навык проектирования конечных автоматов (state machine) для моделирования бизнес-процессов и workflow. Включает определение состояний, переходов, условий переходов (guards) и обработку граничных случаев.

## Когда использовать
- Создание workflow с множеством состояний
- Моделирование бизнес-процессов с ветвлениями
- Определение жизненного цикла сущности
- Проектирование асинхронных процессов с ожиданием

## Когда НЕ использовать
- Для простых линейных процессов без ветвлений
- Для процессов с бесконечным циклом
- Для написания кода state machine
- Для простых условных переходов без сложной логики

## Входные данные
- Описание бизнес-процесса
- Требования к workflow
- Список возможных состояний
- Правила переходов между состояниями
- Триггеры событий

## Выходные данные
- Спецификация state machine
- Определение всех состояний
- Правила переходов с условиями
- Диаграмма переходов
- Обработчики событий (specification)

## Зависимости
- architecture-design - для интеграции в общую архитектуру
- implementation-planning - для планирования реализации

## Режимы отказа
- Несоответствие state machine бизнес-процессу
- Мёртвые состояния (без входящих переходов)
- Циклы без выхода
- Необработанные граничные случаи

## Шаблоны и чек-листы

### Шаблон State Machine Specification
```markdown
## States
- state_name: Название состояния
  description: Описание
  initial: true|false
  final: true|false

## Transitions
- from: STATE_A
  to: STATE_B
  trigger: event_name
  guard: condition
  action: action_to_execute

## Guards
- guard_name: Описание условия
  expression: логическое выражение

## Edge Cases
- case: описание
  handling: способ обработки
```

### Чек-лист
- [ ] Все состояния определены и описаны
- [ ] Все переходы определены с триггерами
- [ ] Guards определены для условных переходов
- [ ] Начальное и конечное состояния определены
- [ ] Граничные случаи обработаны
- [ ] Диаграма переходов создана
- [ ] Нет мёртвых состояний
- [ ] Нет бесконечных циклов без выхода
