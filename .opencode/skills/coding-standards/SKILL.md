# Coding Standards

## Описание
Навык определения стандартов кодирования для проекта. Включает стиль кода, правила линтинга, форматирования, именования и документации.

## Когда использовать
- Создание нового проекта
- Обновление существующих стандартов
- Определение конвенций для команды
- Аудит соответствия стандартам

## Когда НЕ использовать
- Для написания конкретного кода
- Для рефакторинга отдельных модулей
- Для проверки качества кода (используйте architecture-review)

## Входные данные
- Язык программирования
- Фреймворки и библиотеки
- Стандарты индустрии
- Предпочтения команды

## Выходные данные
- Style guide проекта
- Правила линтинга (конфигурация)
- Правила форматирования
- Конвенции именования
- Примеры кода

## Зависимости
- Нет (базовый навык)

## Режимы отказа
- Противоречивые стандарты
- Невыполнимые требования
- Несоответствие инструментам
- Слишком строгие правила

## Шаблоны и чек-листы

### Шаблон Style Guide
```markdown
# Coding Standards: {Язык/Фреймворк}

## Форматирование
- Отступ: 2 пробела (или 4)
- Максимальная длина строки: 100 символов
- Кодировка: UTF-8

## Именование
- Функции: camelCase / snake_case
- Классы: PascalCase
- Константы: UPPER_SNAKE_CASE

## Комментарии
- Документация для public API
- Inline для сложной логики

## Структура
- Модульность
- SRP
- DRY
```

### Чек-лист

- [ ] Инструменты интегрированы
- [ ] Правила именования определены
- [ ] Документация задокументирована
