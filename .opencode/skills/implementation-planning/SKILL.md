# Implementation Planning

## Описание
Навык планирования реализации архитектуры системы. Включает декомпозицию задач, определение зависимостей, оценку сроков и распределение ресурсов.

## Когда использовать
- Перед началом реализации сложного компонента
- При планировании крупного проекта
- При определении roadmap разработки
- При распределении работ между командами

## Когда НЕ использовать
- Для простых задач без зависимостей
- Для написания кода
- Для оценки отдельных функций

## Входные данные
- Архитектурные спецификации
- Бизнес-требования
- Ограничения по срокам
- Доступные ресурсы

## Выходные данные
- План реализации
- Декомпозиция задач
- Зависимости между задачами
- Временная оценка
- Распределение ответственности

## Зависимости
- architecture-design - для понимания архитектуры

## Режимы отказа
- Нереалистичные планы
- Пропущенные зависимости
- Недостаточная детализация
- Неучтённые риски

## Шаблоны и чек-листы

### Шаблон Implementation Plan
```markdown
# Implementation Plan: {Название проекта}

## Фазы реализации

### Phase 1: {Название}
- Tasks:
  - [ ] Task 1: description
  - [ ] Task 2: description
- Dependencies: phase_0
- Timeline: Week 1-2

### Phase 2: {Название}
- Tasks:
  - [ ] Task 3: description
- Dependencies: Phase 1
- Timeline: Week 3-4

## Milestones
| Milestone | Date | Criteria |
|-----------|------|----------|
| MVP | 2024-Q1 | Features delivered |

## Risks
| Risk | Impact | Mitigation |
|------|--------|------------|
| Risk 1 | High | Mitigation strategy |
```

### Чек-лист
- [ ] Задачи декомпозированы до управляемого размера
- [ ] Зависимости идентифицированы
- [ ] Временная оценка реалистична
- [ ] Ресурсы учтены
- [ ] Риски идентифицированы
- [ ] Milestones определены
- [ ] Критерии приёмки заданы
