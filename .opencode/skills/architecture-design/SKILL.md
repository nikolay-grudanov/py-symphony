# Architecture Design

## Описание
Навык систематического проектирования архитектуры программной системы. Включает анализ требований, определение компонентов, проектирование границ и интерфейсов, документирование архитектурных решений с обоснованием компромиссов.

## Когда использовать
- Создание новой архитектуры для зеленого проекта
- Рефакторинг существующей системы
- Проектирование крупных компонентов или подсистем
- Определение интеграционных точек между сервисами

## Когда НЕ использовать
- Для изменений внутри отдельного компонента
- Для написания конкретного кода
- Для рефакторинга отдельных функций или классов
- Для простых баг-фиксов без архитектурных изменений

## Входные данные
- Бизнес-требования к системе
- Функциональные требования
- Нефункциональные требования (производительность, масштабируемость, безопасность)
- Технические ограничения (инфраструктура, бюджет, сроки)
- Существующая архитектура (при рефакторинге)

## Выходные данные
- Software Design Document (SDD)
- Architecture Decision Records (ADR)
- Архитектурные диаграммы (C4, UML или подобные)
- Спецификации компонентов и интерфейсов
- Обоснование архитектурных решений

## Зависимости
- coding-standards - для определения стандартов качества кода
- implementation-planning - для планирования реализации

## Режимы отказа
- Несоответствие архитектуры требованиям системы
- Архитектурные противоречия между компонентами
- Неучтённые ограничения инфраструктуры
- Недостаточная масштабируемость

## Шаблоны и чек-листы

### Шаблон ADR
```markdown
# ADR-{номер}: {Краткое название решения}

## Статус
Предложен | Принят | Устарел | Заменён

## Контекст
Описание проблемы или контекста, требующего решения.

## Решение
Описание принятого решения.

## Последствия
### Положительные
- ...

### Отрицательные
- ...

## Альтернативы
- Альтернатива 1: описание
- Альтернатива 2: описание
```

### Чек-лист
- [ ] Требования проанализированы и задокументированы
- [ ] Компоненты определены и их ответственности ясны
- [ ] Границы между компонентами определены
- [ ] Интерфейсы и контракты задокументированы
- [ ] Архитектурные компромиссы задокументированы с обоснованием
- [ ] Нефункциональные требования учтены
- [ ] ADR созданы для ключевых решений
- [ ] Диаграммы созданы для визуализации архитектуры
